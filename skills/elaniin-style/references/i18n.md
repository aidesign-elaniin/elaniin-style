# Internationalization / i18n (DESIGN.md sections 12 and 13)

> Load this when a site is bilingual or Spanish. Code: `templates/i18n/` (see its README). It needs a server (`proxy.ts`); on a static export
> (`output: "export"`, the site-starter) see "Static export" at the end.

## 13.1 Languages and URLs

- Locales `en` (default, `x-default`) and `es`. `<html lang>` and URLs carry no region. Formatting with `Intl` does: **English `en-US`, Spanish El Salvador `es-SV`**
  (decimal point, comma for thousands, `$` before the amount, 12-hour clock with "p. m."): "1,234.5", "99.98%", "$128.50", "$12,400", "2:30 p. m.".
  One map in `format.ts` (NumberFlow uses the same). Times go through `plainSpaces`: Intl writes the space of "p. m." as a no-break space in Node and as a plain
  one in Chrome, which broke hydration, so every no-break or narrow no-break space becomes a plain one.
- **English has no prefix** (`/`, `/solutions`), **Spanish lives under `/es`** (`/es`, `/es/soluciones`). `/` is the English home with no redirect. `/en/...` redirects (308)
  to the unprefixed URL, so there is one URL per page.
- **Slugs are translated** and defined ONCE in the route table (`routes.ts`: an entry per page with its path in each language). No page answers under a slug of the other
  language. The folder under `src/app/[lang]/` is named after the ENGLISH slug (`app/[lang]/solutions/page.tsx`); `resolveLocale` rewrites `/es/soluciones` to it and answers 404 to
  `/es/solutions`. Only exact slugs are translated; a nested path is its own entry. **Every new page is added to the route table FIRST, or it answers 404.**
- Anchor ids stay English in both languages (`home`, `routes`, `solutions`, `engagement`, `method`, `cases`, `research`, `contact` in `anchors.ts`).
- No automatic redirect from `Accept-Language` (it hides a language from crawlers and surprises people who share links).

## 13.2 Language switch

A compact `EN | ES` pair of **links**, not a button, in the nav on the right (before the buttons, visible from 1024px), at the bottom of the mobile sheet, and in the footer legal row.
Each goes to the **same page in the other language** (route table), has `hreflang`, `lang` and the language name as accessible name, the current one `aria-current="true"`; no cookie.
It lands on the section of the home the visitor is reading now (ids are the same in both languages, measured when they click; `current-section.ts`), on the top when on the hero or
on a page without sections, never on the stale `#hash` of the address bar; without JS it is a plain link to the top. Style: DM Sans body-sm weight 500, 32px tall, 8px side padding, a 1px
`|` separator; current in `text-primary`, the other in `text-secondary` (hover primary); over dark themes the on-dark tokens; no flags (countries, not languages), no blue.

## 13.3 SEO

`<html lang>` per page (text in the other language inside a page carries its own `lang`). Every page has its **own hand-written** translated `<title>` and description (never machine-generated at
build); home titles are brand-first ("Brand | …"); a sub-page title is a full string in each language (`title.absolute`) so no template appends the brand twice. Each page declares a
**self-referencing canonical** and `alternates.languages` (`en`, `es`, `x-default` → English) through `generateMetadata` / `buildMetadata(lang, route, page)`; the sitemap lists both URLs per page with
the same alternates. Open Graph: `og:locale` `en_US` and `es_LA`, titles from the same dictionary. The review site stays `noindex, nofollow` (meta and `X-Robots-Tag`; `ALLOW_INDEXING=true` lifts it
only on the real production project and REQUIRES `SITE_URL`; no `robots.txt` with `Disallow`); `hreflang` is still emitted so it can be tested. Brand and product names are never translated; image `alt` is.

## 13.4 Rules for every section

1. No visible string lives in a component: every string (including `aria-label`, `alt`, placeholders, validation messages, button labels and the text inside decorative mocks) comes from a dictionary.
2. Dictionaries are **typed TypeScript objects**, one file per section and language (`src/content/en/<section>.ts`, `.../es/...`), typed against ONE `src/content/schema.ts`, so a missing or extra key fails `tsc`. English first; Spanish is a translation reviewed by a person.
3. Data files split neutral data (ids, hrefs as route keys, icons, spans, accents, numbers) from text (titles, excerpts, labels, units), keyed by the same id.
4. Layouts are tested with the Spanish copy (20-30% longer): no fixed widths on text, buttons grow or wrap, cards never rely on a line count.
5. Numbers, dates and money go through `Intl` with the page locale; no hard-coded month names or separators.
6. Sentences are never built by concatenating strings: one string with placeholders (`{id}`, `{n}`, `{place}`) filled with `fill()` (`template.ts`), or split at the placeholder when a live element goes inside; plurals use `Intl.PluralRules`.
7. Links between pages go through ONE helper `href(routeKey, lang, anchor?)`; neutral data stores a `Target = { route, anchor } | null` (`null` = a page that does not exist yet, renders `#`; the gate rejects `#` in a published page); no hard-coded paths.
8. Server first: the dictionary is read in Server Components and passed to client leaves as props.
9. Forms send the language with the submission; success and error messages come from the dictionary.
10. Mono uppercase tags keep their accents (Á, É, Ñ) in Spanish.

## 13.5 Technical shape (Next.js 16)

Routes under `src/app/[lang]/` (`layout.tsx` sets `<html lang>`, `generateStaticParams` returns `en` and `es` so both are statically rendered); `icon.svg`, `globals.css`, `sitemap.ts` stay at the `app` root.
`src/proxy.ts` (the Next 16 name for middleware) calls the pure `resolveLocale`: an English slug of the table is rewritten to `/en/...`, a Spanish slug to its internal folder under `/es/...`, `/en/...` is redirected (308) to the
unprefixed URL, uppercase `/ES` or `/EN` to lowercase (the query string is kept), and everything else is rewritten to `/<lang>/404` (the catch-all calls `notFound()`). Segments are matched whole (`/english` is not `/en`);
the matcher skips only Next internals and real static files by extension. The proxy also writes the `region` cookie. `getLang()` and `getCopy(section)` read `lang` through `next/root-params`; an unknown language is a 404. Server
wrappers (Nav, Footer, Hero, Clients, Research, Solutions, Cases, Cta) are async; client parts are the nav client, scenes and visuals. Public origin: `SITE_URL`. **Tests (Vitest, `npm test`)**: routes, proxy rules (translated slugs),
metadata, sitemap, dictionaries (every id has copy in both languages, placeholders present), formats, the switch, and two guards: `copy-guard` (Spanish text in `src/app` or `src/components`) and `jsx-literals` (parses the JSX and flags ANY literal
text node or literal `aria-label`, `alt`, `placeholder`, `title`, in any language; proper names and invented brands on its allow list). No i18n library is needed for two languages.

## Implementation notes (DESIGN.md section 12)

Stack: Next.js (App Router, TypeScript), Tailwind v4, `motion` for components, plain CSS for micro-interactions; GSAP only if a section needs scroll choreography `motion` cannot do. Tokens live in `globals.css` under
`@theme` mirroring the design file; Tailwind's default palette, radii, shadows, type sizes, easings and breakpoints are reset so only the tokens compile. Fonts via `next/font/google` exposed as `--font-instrument-sans`,
`--font-dm-sans`, `--font-geist-mono`. Type sizes are fluid between the mobile and desktop values. `CountUp` counts ONCE (first time 60% on screen), `replayKey` is the only way to replay. **`body { overflow-x: clip }`, never `hidden`**
(with `hidden`, locking the page scroll while the mobile menu is open turned `body` into a scroll container and the sticky bar scrolled away). A global `MotionConfig reducedMotion="user"` lives in the providers (transforms off, opacity
kept); durations and easings come from `motion.*` tokens (`lib/motion.ts`); where JS needs a literal color use `lib/tokens.ts`, a mirror of the theme. Rules for animated mocks: gate every loop with `useInView`; render the final meaningful state
under reduced motion; deterministic first render (no `Math.random`); hold the finished state ~2.5s before restarting, steps ~900ms; color changes in discrete steps up the blue ramp; scroll reveal animates content only, never a cell background
on a hairline grid; the mock is `aria-hidden`. Plain CSS (`rise`) for the hero entrance so it does not wait for hydration.

## Static export (the site-starter)

`output: "export"` has no proxy, so the unprefixed English URL cannot be rewritten. Adaptation: generate BOTH languages with a prefix (`/en/...`, `/es/...`) from `generateStaticParams`, keep the same route table, dictionaries, metadata
(`alternates.languages`, canonical, `x-default` → `/en/`), switch and tests, and add a root `index.html` that links (or meta-refreshes) to `/en/`. This departs from the "English without prefix" decision; say so in the delivery report and
move to the server variant when the project is deployed on a platform with a proxy.

## What is NOT done in the reference yet

The English copy is a translation of invented sample content; the real copy is written with the real content, section by section, English first. The route table grows with each page (slug in both languages, then the copy in both dictionaries).
